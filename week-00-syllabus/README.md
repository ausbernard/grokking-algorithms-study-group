## Purpose of This Study Group
---
This group is designed for both **new and experienced** engineers who want to:

- Create a consistent algorithm practice habit
- Support beginners without boring advanced engineers
- Move together chapter-by-chapter
- Build interviewing fluency
- Produce real GitHub code each week

## Weekly Workflow
---

1. **Read** the assigned chapter
1. **Solve** book exercises
1. **Complete** stretch/interview-level problems
1. **Commit** solutions to GitHub under the proper week folder
1. **Meet** weekly to discuss & pair-program
1. **Reflect** by writing 3 takeaways in your `README.md`


## 📝 WEEKLY MEETING TEMPLATE (60–90 minutes)

1. Warm-Up Discussion (5–10 min)

   - Quick round: “Biggest insight from this week’s reading”

2. Review Key Concepts (10–15 min)

   - Facilitator explains main ideas
   - Reference code examples

3. GitHub Walkthrough (10–15 min)

   - Volunteers share solutions (share the problem, time and space complexities, and solution)

4. Group Exercise (20 min)
    - Solve a fresh problem together on a shared pad
    - Discuss pitfalls

5. Breakout Interviews (10–20 min)
    - 1 partner interviews, 1 codes
    - Swap
    - Debrief

6. Plan Next Week (5 min)
    - Assign readings
    - Assign problems
    - Optional advanced challenge

## 🗓️ Structure & Weekly Flow
Each week follows the same rhythm:

### 1. Read the assigned chapter(s)
Usually 1 chapter per week, occasionally 2 if shorter.
### 2. Work through the coding exercises
Each week’s folder contains:
- Required problems
- Optional stretch problems
- Reference implementations
### 3. Upload your solutions
Submit via:
- A folder under your GitHub username inside the week directory -- **preferred** 
-or-
- A PR to your own fork
### 4. Weekly meeting
We meet to:
- Summarize the chapter
- Review problem-solving approaches
- Discuss where people got stuck
- Try one harder problem together (live-breakout)
### 5. Meeting notes posted afterward
Notes will be placed under:
`/week-XX-<topic>/notes/`
